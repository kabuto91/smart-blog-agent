## 修正：右侧大片空白（用户纠正 —— 上一轮把问题理解成 hover 态是错的）

### 真正的问题
- 完整图 1920×1015 复核：内容只占左侧约 65%，右侧 35% 是纯背景；标题 + 2 列卡片挤在左边，下面卡片继续往左下堆，没有流到右边。
- 内容右边界约 x=1250、起点 x≈60 → 典型「限宽容器 max-width:1200px 但漏写 margin-inline:auto，靠左」。历史主题里 .wrap/.container 都写了 margin:0 auto 且网格多用 repeat(auto-fill, minmax(...))，截图主题（不在本地 themes 表）是固定 2 列 + 靠左限宽。

### 引入点
- 生成侧 prompt 完全没有「正文区宽度/居中/列数自适应」契约；style-analyzer 也无对应检查。
- 渲染期 THEME_SAFETY_CSS 只管溢出（max-width:100%），不管居中。

### 改动（4 个文件）
- `packages/core/src/lib/theme/theme-splitter.ts`：
  - THEME_SAFETY_CSS 增加 `:where()` 限宽容器 `margin-inline:auto` 兜底；**刻意不给 host 加 width:100%**（左侧固定导航布局靠 host 的 margin-left 偏移，叠加会横向溢出）。
  - 新增 `buildWidthFallbackCss(cssText)`：确定性检测「有 max-width 非 100% 但没有任何 margin … auto」的 .wrap/.container/.section 规则时，才追加带 `!important` 的精确居中修正；已居中的主题不受影响。
- `apps/admin/src/agents/theme-agent.ts`：新增 `LAYOUT_WIDTH_CONTRACT` 注入骨架 prompt —— host 禁止设宽度/栅格列；限宽容器 width:100% + max-width:min(100%-2pad,1440px) + margin-inline:auto；卡片网格必须 repeat(auto-fill/auto-fit, minmax(280px,1fr))，禁止写死 2 列；侧栏无内容时用单列；1920 视口自检内容右边界 ≥85%。
- `apps/admin/src/lib/theme/style-analyzer.ts`：新增 `checkContentWidth` —— 限宽容器未居中 → error；host 被限宽/设栅格 → error；固定列数网格 → warn。
- 测试：style-analyzer.test.ts 37 passed、theme-splitter.test.ts 59 passed（各新增 7 / 2 条）。

### 踩坑（重要）
- `checkContentWidth` 初版用 `(?!100%)` 负向前瞻排除 safety 层的 `max-width:100%`，被 `\s*` 回溯绕过（": 100%" 的空格处通过），把安全兜底层误判成「host 被限宽」→ 生成图测试 reviseCount 0→2、递归上限、断点续生重跑全部页面，4 个用例失败。改为**先提取声明值再判断**（排除 100%/auto/none）后恢复。

## 诊断：新生成「主题 6」列表页不显示文章列表（本轮仅分析，未改代码）

- 线上 Supabase 最新主题「主题 6」(`9dd6bb87…`, 11-13 09:32 生成且激活)；上一版「主题 5」正常。前台 `/blog/archive` 与后台主题预览 list 都走同一 `renderContent`，表现一致；首页正常。
- 根因在生成期配置抽取：新列表页卡片是 `<article class="archive-item"><div class="archive-row">date/title/category</div></article>`，内层 `.archive-row` 命中 `content-extractor.ts` `findRepeatableItemTemplate` L442-450 的 `grid|list|row|feed` 包装启发式 → 把第一个子元素 `<span class="archive-date" data-map="date">` 当成整张列表项模板；`extractDynamicField` L364-371 只遍历模板后代的 data-map，模板自身的没计入 → `fieldMapping: {}`。用 `extractContentConfig(list.html)` 现场复现，输出与 DB 里的 `theme_pages.list.contentConfig['article-list']` 完全一致（排除数据损坏/人工编辑）。

- 坑：只把 itemTemplate 改成整张卡片会让列表**全空**——`removeSampleItems(container, template, host)` 删掉样例 article 时把位于其内部的 host 一起删了，clones 追加到游离节点。必须同时修宿主选择（`template.contains(host)` → host 退回 container）。
- 修复方向（探针已验证有效）：生成侧「唯一包装」分支要求 first 含 ≥2 个 data-map 或与 root 字段集一致才下钻 + fieldMapping 计入模板自身；渲染侧收紧 LIST_HOST_CLASS_RE / 修正 host 回退；存量主题 6 重新抽取 list 页 contentConfig 或重新生成。把内层容器改名避开 row 启发式 + 完整模板（或清空模板让渲染侧从 DOM 推导）后，6 篇文章、6 个真实链接、无样例残留。
