# 2026-11-11

## 诊断：不同页面导航栏头像不一致（首页无 / 列表页有）

- 现象：首页站点标题左侧无作者头像，列表页/详情页有。前台所有页面共用 `themes.layout_html` 的同一份 `nav.site-nav`，数据层面导航完全一致。
- 根因：`packages/core/src/lib/theme/content-renderer.ts` 的 `renderContent` 末尾两个头像后处理函数在**整篇文档**范围内去重，结果依赖各页面正文片段结构：
  1. `ensureMultipleAvatarPlaces`（L324-368）：只在 `[data-page-host]` 内用**宽口径**（任意类名含 avatar / img.avatar / data-content=author-avatar）检查；首页侧栏作者卡只有文字无头像 → 注入 `<img class="avatar">`。
  2. `ensureSingleAuthorAvatar`（L419-432）：用**窄口径** `collectAvatarElements`（L406-412，仅 `[data-content="author-avatar"]` / `img.avatar`）收集全文档头像，>1 时保留"正文区内带 author/sidebar 祖先"的那个，其余 `remove()` → 首页导航头像被删。
  3. 列表页正文是 `<div class="avatar"><img data-map="author-avatar">`：宽口径算"已有头像"故不注入，窄口径又不算候选 → 全文档只剩导航头像 → 保留。详情页无合格作者容器 → 同样保留。
- 单测 `content-renderer.test.ts:1046-1058` 明确断言 `nav img` 被删除，说明"删导航头像"是既有设计意图，与"站点级 chrome 全站一致"的要求冲突。
- 验证方式：从 `data/theme-sessions.db` 导出激活主题 layout/pages/site_config，用 jiti 直接调用 `mergeThemePage` + `renderContent` 真实渲染，输出三个页面 nav.outerHTML 对比，已复现（临时脚本已清理，未改动项目文件）。
- 修复方向：把头像注入/去重限定在正文区作用域，nav/header/footer 列为保护区；统一两处头像识别口径；`blog.ts` 传入的 `navClearance: pageType !== "home"` 在 `mergeThemePage(_options)` 中已被忽略，不是差异来源。

## 诊断：主题生成每次都要修订多次（本轮仅分析，未改代码）

- 实证探针（临时 `apps/admin/src/agents/__probe-revise.test.ts`，跑完已删除）：mock LLM 输出固定，只让 judge 首轮 55 分、次轮 95 分。结果 `reviseCount=3`（maxAttempts=3 全耗尽）、`skeletonCalls=4`（骨架整树重建 3 次）、`judgeCalls=2`；默认 `recursionLimit=25` 直接抛 `GraphRecursionError`，调到 60 才跑完。阶段序列：judge → revise → skeleton → 三页 → validator → audit → revise → … 连续 3 轮，中间从未重新评分，最后 gate → judge(95) → commit。
- 根因 1（主因）：`qualityScore`/`qualityDimensions` 是 last reducer 且只在 `judge` 节点更新；`computeRevisePlan` 在 `routeAfterAudit` 也读它们。修订回到 audit 时读到上一轮 judge 的**陈旧低分** → 无条件再触发 revise；`visualPolish` 属 `SKELETON_DIMENSION_KEYS` → `skeletonFix` 整树重建骨架+三页，直到预算耗尽。与模型质量无关，是状态机 bug。
- 根因 2：头像口径冲突。`SKELETON_SYSTEM_PROMPT`(theme-agent.ts L206)、`JUDGE_SYSTEM_PROMPT`(theme-graph.ts L679)、`style-analyzer.ts` L340-344 都还按「全站只允许 1 个头像」，而页面 prompt 允许正文放 `AVATAR_PLACEHOLDER`，且本日已把渲染契约改成「导航/正文各自独立」→ LLM 怎么做都会被判重复 → 扣分/error → 修订；visualPolish 低分又触发骨架重建。
- 根因 3：`style-analyzer.ts` L323 对**任何**骨架未定义类名都报 error（LLM 自由设计必然产生工具类）；`feedback`/`validation` 是 merge reducer，修订时 `buildPagePayload` 把历史 feedback 全量回传、旧问题不清除。
- 根因 4：`routeAfterAudit` 与 `routeAfterJudge` 两处复用同一计划；`scoreThreshold=70`、`maxAttempts=3`（fastMode 2），judge 主观低分即整树重建。
- 建议修复顺序（待用户确认）：① revise 前清空/标记 stale 的 qualityScore、qualityDimensions、validation、feedback，audit 只看本轮确定性结果；② judge 低分只触发一次定向修订；③ 统一头像口径到新契约（JUDGE prompt + style-analyzer + skeleton/detail prompt）；④ 未定义类名降为 warn 或按数量阈值；⑤ feedback 每轮重置。
