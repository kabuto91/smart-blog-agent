# 精选文章内置区块实现计划（文章管理新增「精选/最新文章」管理 + 渲染自动识别替换）

## 摘要

文章管理后台新增一个**内置区块**，用于管理「精选文章」与「最新文章」：
- **精选文章**：手动勾选/排序若干篇文章，配置存 `site_config`（JSON 字段 `featuredArticleIds`）。
- **最新文章**：自动取最新 N 篇（沿用现有 `article-list` / `HOME_PAGE_ARTICLE_LIMIT` 逻辑，无需手选）。
- 渲染时主题里被识别为「精选文章」的区块（`data-content="featured-articles"`）自动用精选文章填充；「近期/最新/文章列表」区块（`data-content="article-list"`）维持最新文章填充。
- 设计上预留「后续可支持自定义区块」的扩展性：精选区块按独立 key `featured-articles` 走通用 `dynamic-articles` 类型管线，后续可低成本再加新 key。

数据仍存 `site_config` 无新增表、无 Prisma schema 变更，无需重启 dev server。

- 渲染识别：`renderDynamicField(doc, key, field, dynamicData)` 的第一个参数 `key` 即 `data-content` 值，可据此区分「精选」与「最新」区块。
- `site_config` 存储在 [site-config.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/site-config.ts)，`getSiteConfig/updateSiteConfig` 只处理 `EDITABLE_KEYS`（[field-registry.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/field-registry.ts#L46) 的 GLOBAL_FIELDS），因此精选配置需单独读写，避免污染后台「站点设置」文本表单。
- 文章按 id 取数：`getArticleById`/`getArticles` 已存在（[articles.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/articles.ts#L162)），可复用。

## 拟改动

### 改动 1：site-config.ts —— 新增精选文章 ID 列表的读写（独立于 EDITABLE_KEYS）

新增：
```ts
export const FEATURED_ARTICLES_KEY = "featuredArticleIds"

/** 读取后台配置的精选文章 ID 列表（按顺序）。 */
export async function getFeaturedArticleIds(): Promise<string[]> {
  try {
    const row = await prisma.siteConfig.findUnique({ where: { id: 1 } })
    const raw = row?.config ? (JSON.parse(row.config)[FEATURED_ARTICLES_KEY] as unknown) : undefined
    if (Array.isArray(raw)) return raw.filter((x) => typeof x === "string")
  } catch {
    // table may not exist yet
  }
  return []
}

/** 保存精选文章 ID 列表（合并写入 site_config.config，不影响其它字段）。 */
export async function saveFeaturedArticleIds(ids: string[]): Promise<void> {
  const row = await prisma.siteConfig.findUnique({ where: { id: 1 } })
  const current = row?.config ? JSON.parse(row.config) : {}
  current[FEATURED_ARTICLES_KEY] = ids
  await prisma.siteConfig.upsert({
    where: { id: 1 },
    create: { id: 1, config: JSON.stringify(current) },
    update: { config: JSON.stringify(current) },
  })
}
```
说明：刻意**不**加入 `EDITABLE_KEYS`，从而不影响站点设置文本表单。

### 改动 2：articles.ts —— 按 id 列表有序取数

新增：
```ts
export async function getArticlesByIds(ids: string[]): Promise<ArticleListItem[]> {
  if (ids.length === 0) return []
  const rows = await prisma.article.findMany({
    where: { id: { in: ids }, published: true },
    include: ARTICLE_INCLUDE,
  })
  const byId = new Map(rows.map((r) => [r.id, r]))
  // 按传入顺序返回，未发布/不存在的自动跳过
  return ids.flatMap((id) => (byId.get(id) ? [byId.get(id)!] : []))
}
```

## 假设与决策

- 精选文章 ID 存 `site_config.config.featuredArticleIds`（`string[]`），**不加** Prisma 列，避免迁移与重启。
- 精选配置**不进** `EDITABLE_KEYS`，不影响站点设置文本表单，仅由「文章管理」内置区块与专用 API 读写。
- 渲染用「data-content key = `featured-articles`」区分精选/最新；类型仍为 `dynamic-articles`，复用现有动态列表管线与 `data-map` 模板（标题/摘要/日期/分类/链接/封面）。
- 未配置任何精选时，`featured-articles` 区块不渲染或显示为空（走现有动态列表空数据处理），不报错、不清空整页。
- 最新文章维持现状（最新 N 篇），本次不动 `HOME_PAGE_ARTICLE_LIMIT`。
- 已生成的历史主题若把精选区块标成了 `article-list`，不受影响（按最新文章展示）；仅新生成的精选区块会用 `featured-articles`。
