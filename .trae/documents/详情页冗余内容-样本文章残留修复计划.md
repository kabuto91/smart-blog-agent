# 修复计划：详情页冗余内容（样本文章残留 + 标题头被冲掉）

## 摘要

重新生成的主题（"主题 2 #2"，今日 15:19）详情页出现两处异常（已实测复现）：

1. **样本占位文章残留在页面上**：LLM 生成的示例正文（"极简，并非空无一物…"的整篇假文章）没有被真实文章替换，与真实文章内容同时显示
2. **文章标题头被冲掉**：`[data-content="article-body"]` 容器内的标题/分类/日期被整篇 contentHtml 覆盖

期望行为：详情页 = 骨架（导航/页脚）+ 替换后的真实文章详情。

**好消息**：核心修复全部在渲染层（render-time），当前主题无需再次重新生成，改完代码立即生效。

## 根因分析（实测确认）

### 主因：`[data-map="body"]` 在容器外，渲染器回退逻辑冲掉标题头

新主题详情页 HTML 结构（DB 导出，[tmp-detail.html]）：

```html
<div class="article-header">
  <article data-content="article-body" data-content-type="article-body">
    <span data-map="category">设计随笔</span>
    <h1 data-map="title">在留白处寻找呼吸…</h1>
    <p data-content="subtitle">…</p>
    <span data-map="date">2024-05-12</span> …
  </article>                        ← 容器：只有标题头信息
</div>
<div class="article-body">
  <div data-map="body">…样本假文章…</div>   ← 正文占位在容器【外部】（兄弟节点）
</div>
```

而 prompt 期望的结构是 `[data-map="body"]` 位于 article 容器**内部**。[content-renderer.ts L588-590](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\content-renderer.ts#L588-L590) 的 article-body 渲染逻辑：

```ts
const bodyTarget = container.querySelector('[data-map="body"]') ?? container
bodyTarget.innerHTML = article.contentHtml
```

- `container.querySelector` 只查**后代** → 找不到（body 在外面）
- 回退 `bodyTarget = container` → `container.innerHTML = contentHtml` → **标题头（title/category/date/lead）整体被替换为原始文章 HTML**（实测：article-body inner 变成 `<h1>开源项目的社区运营</h1><p>保持内容精炼…`）
- 容器外的 `[data-map="body"]`（含整篇样本假文章）**从未被替换** → 残留（实测：渲染后页面 `contains sample text(留白): true`，`inside article-body: false`）

### 促因：上一轮 prompt 强化引发"双重标记"，修复主因后会反向覆盖真实值

实测 DB 详情页 contentConfig key 顺序：`article-body, category, title, subtitle, date, …, p-1~p-6, h2-1, h2-2, tag-1~3, author-*`

- 新 prompt"必须标记所有标题/段落"导致 LLM 给本就有 `data-map` 的元素（category/title/date）**又加了 `data-content`** → 这些 text 字段值是**样本值**（如 category="设计随笔"）
- 渲染循环按插入顺序执行：`article-body` 最先（写入真实值）→ 随后 `renderTextField("category", "设计随笔")` 用**样本值覆盖真实分类**
- LLM 还把样本假文章段落标成了 p-1~p-6/h2-1/h2-2 字段（contentConfig 噪音）

### 背景约束

`renderBlogTheme` 以 `{ pageSpecific: true }` 调用 `renderContent`（commit 8462840 引入的拆分式渲染），`pruneDetailPage` 等清理逻辑**不执行**——页面正确性完全依赖渲染替换逻辑，所以占位内容必须被正确替换而非依赖事后清理。

## 修复方案

### 修复 1：article-body 正文占位全局查找（核心）

文件：[content-renderer.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\content-renderer.ts) `renderDynamicField` article-body 分支（L588-590）

```ts
const bodyTarget =
  container.querySelector('[data-map="body"]') ??
  doc.querySelector('[data-map="body"]') ?? // 容器外查找（LLM 可能把正文区放在容器外）
  container
bodyTarget.innerHTML = article.contentHtml
```

效果：标题头保留（data-map 元素由前面的循环填真实值），样本正文被真实文章替换。`data-map="body"` 仅存在于详情页结构，全局查找无副作用。

### 修复 2：renderTextField 跳过 data-map 元素（防样本值覆盖）

文件：[content-renderer.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\content-renderer.ts) `renderTextField`（L495+）

在跳过 nav-list 容器文字的既有判断附近新增：

```ts
// data-map 元素由动态字段渲染填充真实值（如文章标题/分类/日期），
// 文本字段再用样本占位值覆盖会冲掉真实数据
if (el.hasAttribute("data-map")) continue
```

### 修复 3：提取层卫生（防未来生成再污染）

文件：[content-extractor.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\content-extractor.ts)

**3a. `markUnmarkedTextUnits`**：跳过 `[data-map="body"]` 后代——正文占位区整块运行时替换，标记它们只会产生无意义字段：

```ts
.filter(
  (el) =>
    (el.textContent ?? "").trim().length > 0 &&
    el.closest("[data-content]") === null &&
    el.closest('[data-map="body"]') === null
)
```

**3b. 提取循环清洗**：`extractContentConfig` 主循环跳过 `[data-map="body"]` 后代的元素并移除其 data-content 标记（LLM 这次手写了 p-1~p-6 标记，需剥离进 config 的噪音）：

```ts
for (const el of elements) {
  if (el.closest('[data-map="body"]')) {
    el.removeAttribute("data-content")
    el.removeAttribute("data-content-type")
    continue
  }
  ...
}
```

### 修复 4：detail prompt 结构硬约束

文件：[theme-agent.ts](d:\frontProjects\agent\smart-blog-agent\src\agents\theme-agent.ts) `PAGE_SPEC.detail.bodyPrompt` 数据绑定规则追加：

```text
- <div data-map="body"> 必须放在 <article data-content="article-body"> 容器内部（正文占位不能拆到容器外）；
- data-map="body" 内部是会被整块替换的占位正文，不要给其中的元素标记 data-content。
```

## 假设与决策

- 不做 DB 数据手术：当前主题的 p-1~p-6 等 22 个字段中的样本假文章字段（p-1~p-6/h2-1/h2-2）渲染时因元素已被替换而自动 no-op，仅作为后台编辑面板的冗余字段存在，可接受（避免再次重新生成主题）
- renderTextField 的 data-map 跳过是全局的：正常主题中 text 字段元素不会带 data-map（data-map 属于动态绑定），该跳过仅影响双重标记场景
- 不给 validatePageFragment 增加结构校验：修复 1 已让渲染器对结构偏差鲁棒，强制 LLM 重跑修订成本大于收益
- 详情页中静态文本字段（subtitle、tag-1~3、作者区）保持样本值属于主题设计内容（后台可编辑），不在本次修复范围
