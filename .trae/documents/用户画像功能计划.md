# 用户画像（User Profile）功能计划

## 摘要

新增「用户画像」功能：基于已发布文章列表，由 AI 提炼一份描述博客内容方向与写作风格的画像文本；用户可在管理后台查看、手动编辑，并可用开关控制是否在「主题生成」与「文章内容生成」时把画像注入 prompt，使 AI 生成的主题占位内容与文章写作风格与作者保持一致。

## 现状分析

- **文章生成**：[article-agent.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/article-agent.ts) 的 `buildArticleMessages` 构造 `[System, Human]` prompt，由 [api/articles/generate/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/articles/generate/route.ts) 调用；当前不读取任何文章或站点数据。
- **主题生成**：[theme-graph.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-graph.ts) 的 planner → skeleton → 三个 page 节点组装 prompt，[api/themes/generate/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/themes/generate/route.ts) 已加载 `siteConfig` 传入 graph，但未注入任何文章信息。
- **文章数据**：[Article](file:///d:/frontProjects/agent/smart-blog-agent/prisma/schema.prisma#L114-L130) 含 title/excerpt/content/category/tags；[articles.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/articles.ts) 提供 `getArticles` 等查询，可直接复用 Prisma 查询。
- **配置存储**：[site-config.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/site-config.ts) 用 `SiteConfig` 单行 JSON 的 `config` 列存扩展字段（如 `featuredArticleIds` 数组），`textLibrary` 存可复用文本。这是已有的扩展存储模式，无需改表。
- **管理后台**：[admin/settings/page.tsx](file:///d:/frontProjects/agent/smart-blog-agent/src/app/admin/settings/page.tsx)（博客设置）已有「主配置表单 + 可复用文本独立区块」的布局，适合新增「用户画像」独立区块。

## 设计决策（Assumptions & Decisions）

1. **生成方式**：AI 从文章列表自动生成 + 手动编辑。提供「从文章列表生成画像」按钮，AI 分析最近 20 篇已发布文章（标题/摘要/分类/标签/正文前 400 字）生成画像；生成结果写入文本域，可手动修改后保存。
2. **注入范围**：主题生成 + 文章内容生成两个流程（用户已确认）。自定义页面生成不做修改。
3. **开关控制**：加开关 `userProfileEnabled`，默认开启；关闭后生成时跳过注入。
4. **存储**：存入 `SiteConfig.config` JSON 的两个键（复用 `featuredArticleIds` 模式，**不新增 Prisma 表、不跑迁移**）：
   - `userProfile: string` — 画像文本
   - `userProfileEnabled: boolean` — 注入开关
   - 两个键刻意不进 `EDITABLE_KEYS`，避免污染站点设置文本表单（与 `featuredArticleIds` 一致）。
5. **API**：新增 `GET/PUT/POST /api/user-profile`（GET 读、PUT 保存画像+开关、POST 触发 AI 生成）。
6. **不变量**：画像是「内容方向与写作风格」参考；生成主题时指导设计取向与占位内容，生成文章时指导选题与文风；**用户本次明确要求始终优先于画像**。

## 变更内容（Proposed Changes）

### 1. `src/lib/site-config.ts` — 画像存取

新增常量与两个函数（模式完全对齐 `getFeaturedArticleIds`/`saveFeaturedArticleIds`）：

- 常量：`USER_PROFILE_KEY = "userProfile"`、`USER_PROFILE_ENABLED_KEY = "userProfileEnabled"`
- `getUserProfile(): Promise<{ profile: string; enabled: boolean }>` — 读 `site_config.config` 两键；`enabled` 默认 `true`，`profile` 默认 `""`；`try/catch` 兜底。
- `saveUserProfile(profile: string, enabled: boolean): Promise<void>` — 读现有 config JSON → 合并两键 → `upsert` 写回（保留其它键）。

### 2. `src/lib/user-profile.ts`（新增）— AI 画像生成

- `export const USER_PROFILE_SYSTEM_PROMPT`：角色为资深内容策划编辑，输出 200~300 字中文紧凑画像（不输出 JSON），内容必须基于给定文章、禁止编造；覆盖维度：①主要领域/高频关键词 ②写作风格（语言风格/语气/常用结构）③文章特征（篇幅/格式习惯）④目标读者 ⑤一句话总结（作者是谁/博客核心价值）。
- `export interface ProfileArticleInput { title; excerpt?; category?; tags: string[]; contentPreview? }`
- `export function buildProfilePrompt(articles: ProfileArticleInput[]): string` — 逐篇拼 `标题｜分类｜标签｜摘要`，附正文片段；可单测。
- `export async function generateUserProfile(articles): Promise<string>` — `createLLM(false)` + `[System, Human]` 调用，取文本 trim；失败向上抛由路由兜底。

### 3. `src/app/api/user-profile/route.ts`（新增）— 画像 API

- `GET`：`getUserProfile()` → `{ profile, enabled }`。
- `PUT`：校验 body 后 `saveUserProfile(profile, enabled)`（`enabled` 默认 true）→ `{ success: true, profile, enabled }`。
- `POST`：查询最近 20 篇已发布文章（`published: true`，include category/tags，按 createdAt desc，take 20）；无文章返回 400「暂无已发布文章」；拼 `ProfileArticleInput[]`（正文 `.replace(/\s+/g," ").trim().slice(0,400)`）→ `generateUserProfile` → 成功则 `saveUserProfile`（保留当前 enabled）→ `{ success, profile, articleCount }`；失败 500。
- `export const runtime = "nodejs"`。

### 4. `src/agents/article-agent.ts` — 文章 prompt 注入画像

- `ArticleGenParams` 新增 `authorProfile?: string`。
- `buildArticleMessages` 中，在「写作要求/要点」之后追加（若有值）：
  ```
  【作者画像（保持一致的选题与写作风格，但以用户本次明确要求为准）】
  ${authorProfile}
  ```

### 5. `src/app/api/articles/generate/route.ts` — 文章生成接入

- 引入 `getUserProfile`；构造 `buildArticleMessages` 前取 `{ profile, enabled }`，传 `authorProfile: enabled ? profile : ""`。

### 6. `src/agents/theme-graph.ts` — 主题 prompt 注入画像

- `ThemeGraphInput` 新增 `userProfile?: string`；`ThemeStateAnnotation` 新增 `userProfile: last<string>(() => "")`。
- planner：`generateDesignBrief(llm, userRequest, seeds, userProfile?)`，Human 消息在「用户需求」后追加：
  ```
  【作者画像（博客内容方向与写作风格，供设计取向参考）】
  ${userProfile}
  ```
- skeleton 节点：`userContent += 【作者画像…供占位内容与设计取向参考】`。
- page 节点（home/list/detail 共用 `makePageNode`）：同样追加画像段。
- `buildSkeletonPayload` 与 `buildPagePayload` 均携带 `userProfile: state.userProfile`（Send 子节点需要独立下发）。
- 画像是纯附加字符串，默认空串，不影响现有测试。

### 7. `src/app/api/themes/generate/route.ts` — 主题生成接入

- 引入 `getUserProfile`；构建 `ThemeGraphInput` 时传 `userProfile: enabled ? profile : ""`。

### 8. `src/app/admin/settings/page.tsx` — 管理后台 UI

新增「用户画像」独立区块（放在主配置之后、可复用文本区块之前，风格与可复用文本一致）：

- state：`profile`、`profileEnabled`、`profileLoading`、`profileGenerating`、`profileSaving`、`profileSuccess`。
- `useEffect` 中并行 `fetch("/api/user-profile")` 加载画像与开关。
- UI 元素：
  - 标题「用户画像（User Profile）」+ 说明「描述博客内容方向与写作风格，生成主题/文章时自动注入 prompt」。
  - `<textarea>`（多行）绑定 `profile`。
  - 注入开关：`profileEnabled`（样式沿用现有金棕色调 toggle/双按钮，默认开启）。
  - 按钮：「从文章列表生成画像」（POST，loading 态）+「保存画像」（PUT，成功提示 2s）。
- 新增 handlers：`handleProfileGenerate`、`handleProfileSave`。

### 9. 测试

- `src/agents/article-agent.test.ts`：新增用例「authorProfile 注入写作风格参考」——`buildArticleMessages({ title, mode:"generate", authorProfile:"画像内容" })`，Human 文本 `toContain("画像内容")`。
- `src/lib/user-profile.test.ts`（新增）：`buildProfilePrompt` 输出包含各文章的标题、分类、标签、摘要与正文片段，且包含系统提示要求的维度关键词（如「目标读者」「写作风格」）。
- 现有测试（theme-graph、article-agent、parseGenerated 等）应全部保持通过。

## 验证步骤（Verification）

1. `npx vitest run` 通过全部单测（含新增）。
2. `npm run build`（或 `npx tsc --noEmit`）无类型错误。
3. 手动端到端：
   - 后台「博客设置」能看到画像区块；点「从文章列表生成画像」→ 文本域出现画像、提示文章数；保存后刷新仍在。
   - 生成一篇文章，确认文章风格贴合画像（注入生效）。
   - 关闭开关后再生成文章/主题，确认 prompt 不含画像（注入关闭）。
   - 生成新主题，确认占位内容/设计取向贴合画像内容方向。

## 备注

- 不新增 Prisma 模型/迁移，服务端需重启一次即可（无需重新生成 client）。
- 画像生成失败（LLM 报错/无已发布文章）在前端 alert 提示，不阻塞其它功能。
