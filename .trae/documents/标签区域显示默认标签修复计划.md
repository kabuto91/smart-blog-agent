# 标签区域显示维护标签（而非默认标签）修复计划

## 一、问题描述

页面侧边栏/标签区域的标签，显示的是 LLM 生成主题时硬编码的默认标签，而不是数据库中实际维护的标签。

- **页面实际展示的标签**（首页 /blog、归档页 /blog/archive 均为静态硬编码链接）：
  `retro 复古、synthwave、css、sci-fi、design、cyberpunk`
- **数据库中维护的标签**（`prisma.tag`，经 `/api/tags` 确认）：
  `Next.js、入门、工程化、性能优化、CSS、TypeScript、架构、数据库`

两者完全不同，确认存在此 Bug。

## 二、根因分析

1. **页面标签区是静态硬编码链接**：DOM 检查显示，首页/归档页标签区是普通 `<a href="/blog/tag/retro">RETRO</a>` 形式，**没有任何 `data-content-type="dynamic-tags"` 标记**，标签区容器也没有 `dynamic-tags` 容器（count：0）。
2. **因此 `dynamicData.tags`（数据库标签）无处注入**：渲染器 `renderDynamicField`（[content-renderer.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/content-renderer.ts#L608-L612)）仅对 `[data-content="..."]` 且 `data-content-type="dynamic-tags"` 的容器生效，静态标签链接不在匹配范围。
3. **生成提示词抑制了正确标记**：[theme-agent.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-agent.ts#L256) 第 256 行【内容标记规则】明确将"标签组"归入"普通文本区域"，要求标记为 `data-content-type="text"`，而不是 `dynamic-tags`。整个提示词中只有"文章列表"被描述为动态内容，未告知 LLM 标签/分类列表也可做成动态字段。
4. `content-extractor` 也没有类似 `findUnmarkedNavs` 那样的"未标记标签区自动识别"逻辑，无法兜底。

## 三、修复方案（两级互补）

### 方案 A：渲染侧静态标签云兜底（立即修复现有主题，不需重新生成）

在 `content-renderer.ts` 的 `renderContent` 末尾新增 `renderStaticTagClouds(doc, dynamicData.tags)`：扫描页面中**未标记**的标签链接区，将链接的 `href` 与文本替换为数据库标签。

- **只在 `dynamicData.tags` 非空且页面存在静态 `/blog/tag/` 链接时生效**，不触碰已正确标记 `dynamic-tags` 的主题。
- **作用域限定**（避免误伤）：
  - 父子级含 ≥2 个 `a[href*="/blog/tag/"]` 链接的列表（`ul`/`ol`）/容器
  - 容器自身及其祖先**没有** `data-content` / `data-content-type` 标记（跳过已纳入动态/文本配置的区域）
  - 不在 `nav` / `footer` 内
- **替换策略**：按容器内现有坑位数量，用数据库标签（前 N 个）逐条覆盖现有链接的 `href`（`/blog/tag/{slug}`）与文本（`name`）。保持容器结构与坑位数量不变，最安全、不易回归。
- 复用一个精简的替换逻辑（不引入复杂模板解析/克隆），仅操作 `href` 与 `textContent`。

### 方案 B：生成提示词约定（修复未来 / 重新生成的主题，规范化）

修改 `theme-agent.ts` 的【内容标记规则】：

1. 将 `static {{html}}` 第 256 行中的"标签组"从"普通文本区域（text）"之列移除，明确标签/分类**列表**区域应标记为动态字段。
2. 新增一条动态字段约定（紧邻 `DYNAMIC_ARTICLES_RULE`）：
   > 标签云/分类列表区域用 `<div data-content="tag-cloud" data-content-type="dynamic-tags">` 包裹，容器内首个子元素作为单个标签项模板，用 `data-map="name"` 标记标签名、`data-map="link"` 标记链接。
   > 分类列表同理用 `data-content-type="dynamic-categories"`。

   这样 LLM 生成的新主题标签区会正确标记，`content-extractor` 的现有 `extractDynamicField`（已支持 `dynamic-tags`）可自动提取配置，走正规动态渲染。

## 五、假设与决策

- **决策**：本次聚焦"标签"（用户明确指出的）。分类（categories）如页面存在同类静态分类链接区，用**同一函数**顺带处理（`/blog/category/`），不额外增加工作量；若页面无独立分类展示则不处理。（首页仅有 1 个 `/blog/category/tech` 链接且位于导航，不构成标签云，故实际上分类不会触发。）
- **决策**：静态兜底保持"坑位数量不变、替换内容"，而非重建容器填满全部 DB 标签。原因：不破坏 LLM 生成的布局/样式，规避回归。
- **假设**：数据库标签通过 `dynamicData.tags` 已由各路由注入（归档/首页 route 均已调用 `getTags()`，[blog.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/blog.ts) 的 `toTagData` 提供 `slug` 与 `name`）。已核实。
