# 样式问题修复计划：导航栏塌缩遮挡 + 列表页横向排列

## 摘要

当前激活主题（"主题 2"，工业风）渲染存在两个样式缺陷，均已在浏览器中实测复现并定位到代码级根因：

1. **导航栏被"顶上去"**：固定导航栏塌缩成 1px 高，页面内容从 y=0 开始被导航栏遮挡。
2. **列表页横向排列**：归档页（/blog/archive）的 10 篇文章克隆项全部嵌套进唯一样本项内部，因 flex 行布局横向排开（外层 article 宽度溢出到 3059px）。

两个问题都出在**渲染管线的代码缺陷**（非主题数据问题），修复后存量主题下次渲染即自动生效。

## 根因分析

### 问题 1：导航栏塌缩（--nav-h 被运行时脚本错误置 0）

**证据链**（Playwright 实测 /blog/archive）：
- 布局中固定导航是 `<header class="site-nav">`（`position:fixed; height: var(--nav-h)`），其内部还包了一个普通 `<nav>`，`data-content="main-nav"` 标在 `<ul>` 上（不在 `<nav>` 标签上）
- `htmlInlineNavH: "0px"`、`computedNavH: "0px"`、`bodyPaddingTop: "0px"`、`navRect: {top: 0, height: 1}`
- 样式表本身声明是正确的：`:root { --nav-h: 64px }`、`body { padding-top: var(--nav-h) }`

**根因**：[theme-splitter.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\theme-splitter.ts) 中 `ensureLayoutContract` 注入的运行时测量脚本：

```js
var nav=document.querySelector('nav[data-content="main-nav"]')||document.querySelector('nav')||document.querySelector('header');
var h=0;
if(nav&&window.getComputedStyle(nav).position==='fixed'){h=nav.getBoundingClientRect().height;}
document.documentElement.style.setProperty('--nav-h',h+'px');
```

- 第一个选择器 `nav[data-content="main-nav"]` 落空（该属性在 `<ul>` 上）
- `||` 短路取到**第一个** `<nav>`（header 内的静态包装元素，position: static）
- 只检查了这一个元素是否 fixed → 非固定 → h=0
- 把 `--nav-h: 0px` 内联写到 `<html>` 上，覆盖了样式表的 `:root { --nav-h: 64px }`
- 连锁反应：`body padding-top` → 0（留白消失）、`.site-nav height` → 0（导航塌缩成 1px border）、非 home 页 host 的 `padding-top: var(--nav-h, 0px)` → 0

**注意**：存量主题的 layoutHtml 中已嵌入了旧版脚本（DB 中 tmp-layout.html 可见），`ensureLayoutContract` 只在脚本**不存在**时才注入，必须像 `data-theme-safety` 样式层一样做**版本化替换重注入**才能让存量主题升级。

### 问题 2：列表页文章横向排列（宿主误判）

**证据链**（实测渲染后的 /blog/archive HTML + 几何数据）：
- 列表页动态文章容器结构（与首页不同，**没有** `.post-list` 包装 div，样本项是容器直接子元素）：

```html
<section data-content="article-list" data-content-type="dynamic-articles">
  <article class="post-list-item">…唯一样本…</article>
</section>
```

- contentConfig 的 itemTemplate 恰好也是 `<article class="post-list-item">…</article>`（合法的单项模板）
- 渲染结果：10 个克隆 article 全部**嵌套**在样本 article 内部（实测 `outerArticleChildCount: 12`）
- 嵌套项几何：全部 `top: 533`、`left` 依次 250/531/820（同一行横排）；`.post-list-item` 是 `display: flex`（横向）→ 横向排列 + 溢出

**根因**：[content-renderer.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\content-renderer.ts) 中：
- `findDynamicListHost` 找"第一个含 `[data-map]` 后代的 div/section/article"→ 找到的是**样本项 `<article>` 本身**（它不是宿主而是列表项）
- `resolveListItemTemplate` 先定 host 再定 template：host=样本 article，template=itemTemplate 的 article → `host.appendChild(clone)` 把所有克隆项塞进样本项内部

### 附带问题 A：修复后会出现的双重留白

`mergeThemePage` 对非 home 页无条件设置 `host.style.paddingTop = "var(--nav-h, 0px)"`。本主题骨架已有 `body { padding-top: var(--nav-h) }`，测量脚本修好后列表/详情页顶部将出现 64+64=128px 双重留白。需要在 body 已有 var(--nav-h) 级留白时跳过 host 留白。

### 附带问题 B（次要，可选）：嵌套 data-page-host

保存的 page.html 片段自带 `<div data-page-host="">` 包装（页面生成时 LLM 仿照布局结构输出，`sanitizePageFragment` 未剥离），merge 后产生嵌套 host。视觉无碍（普通 div），本次仅做防御性剥离（低优先级，可选）。

## 修复方案

### 修复 1：导航测量脚本改为"遍历候选取第一个 fixed" + 版本化重注入

文件：[theme-splitter.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\theme-splitter.ts) `ensureLayoutContract` 第 4 步

- 移除现有 `if (!body.querySelector(...))` 守卫，改为**先移除全部旧 `script[data-theme-nav-measure]` 再注入新版**（与 safety 样式层的升级机制一致，存量主题下次渲染自动升级）
- 新脚本逻辑：`querySelectorAll('nav[data-content="main-nav"], nav, header')` 遍历所有候选（文档序），取**第一个 computed position 为 fixed 的元素**测高；无 fixed 元素则置 0（保持"静态/吸顶导航不留白"的原有语义）

```js
(function(){
  var sync=function(){
    var els=document.querySelectorAll('nav[data-content="main-nav"], nav, header');
    var h=0;
    for(var i=0;i<els.length;i++){
      var el=els[i];
      if(window.getComputedStyle(el).position==='fixed'){
        h=el.getBoundingClientRect().height;
        break;
      }
    }
    document.documentElement.style.setProperty('--nav-h',h+'px');
  };
  if(document.readyState==='loading'){document.addEventListener('DOMContentLoaded',sync);}else{sync();}
  window.addEventListener('resize',sync);
})();
```

注：测量时 `<html>` 上尚无内联覆盖，fixed header 高度即样式表声明值（64px），自引用稳定。首页（navClearance=false）与非 home 页均由 body padding 恢复 64px 留白。

### 修复 2：动态列表宿主误判回退（同构检测）

文件：[content-renderer.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\content-renderer.ts) `resolveListItemTemplate`

调整解析顺序：先解析合法 itemTemplate，再找 host；**当合法模板存在、host 不是 container 自身、且 host 与模板同构（同标签 + 同类名集合，均非空）时**，判定 `findDynamicListHost` 把唯一样本项误认成了宿主 → 回退用 `container` 作为宿主：

```ts
export function resolveListItemTemplate(
  container: Element,
  field: DynamicField
): { host: Element; template: Element } | null {
  let template: Element | null = null
  if (looksLikeItemTemplate(field.itemTemplate)) {
    const dom = new JSDOM(field.itemTemplate).window.document
    template = dom.body.firstElementChild
  }

  let host = findDynamicListHost(container) ?? container

  // 宿主与模板同构说明 findDynamicListHost 把唯一样本项误认成了宿主：
  // 真正的宿主是 container 自身，避免克隆项嵌套进样本项（flex 行布局 → 横向排列）。
  if (template && host !== container && isSameElementShape(host, template)) {
    host = container
  }

  if (!template) template = findItemTemplate(host)
  if (!template) return null

  return { host, template }
}

/** 同构判定：标签相同且类名集合一致（要求双方类名非空，避免误伤无类包装容器）。 */
function isSameElementShape(a: Element, b: Element): boolean {
  if (a.tagName !== b.tagName) return false
  if (a.classList.length === 0 || b.classList.length === 0) return false
  return (
    Array.from(a.classList).sort().join(" ") ===
    Array.from(b.classList).sort().join(" ")
  )
}
```

各场景推演（已逐一验证）：
- 列表页（本次 bug）：host 从样本 article 回退为 section → 样本项被 `removeSampleItems` 按"同标签+共享类名"清除，克隆项平铺进 section 垂直堆叠 ✓
- 首页：itemTemplate 是 `<h2>`（非法模板）→ 不触发同构检测，host 保持 `.post-list` div，行为不变 ✓
- ul/ol 宿主、`<a data-map>` 自映射标签项、tags-group 包装等既有结构：同构条件不满足，行为不变 ✓

### 修复 3：双重留白检测

文件：[theme-splitter.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\theme-splitter.ts) `mergeThemePage`

新增 `hasBodyNavClearance(doc)`：遍历布局 `<style>`，匹配 body（或 `html, body`）规则块，检测其中 padding/margin 声明是否引用 `var(--nav-h`（含 `padding: var(--nav-h) 0 0`、`calc(var(--nav-h) + 24px)` 等形式）。已检测到则跳过 host 的 `padding-top`：

```ts
host.innerHTML = pageHtml
if (options?.navClearance && !hasBodyNavClearance(doc)) {
  host.style.paddingTop = "var(--nav-h, 0px)"
}
```

注：仅检测引用 `var(--nav-h)` 的留白（与骨架契约一致、随测量值联动）；字面量 px 留白有歧义（可能是其他设计意图），不做跳过。`renderCustomThemePage`（自定义页 navClearance: true）走同一函数，同样受益。

### 修复 4（可选，低优先级）：剥离片段顶层裸 data-page-host 包装

文件：[theme-splitter.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\theme-splitter.ts) `sanitizePageFragment`（或 `mergeThemePage` 注入前）

若片段顶层只有一个（或多个）裸 `[data-page-host]` 包装 div，剥掉外壳保留内部内容，消除嵌套 host。不影响本次两个主问题的修复效果。

## 假设与决策

- 修复全部落在渲染管线（theme-splitter.ts / content-renderer.ts），**不改 DB 中的主题数据**——`ensureLayoutContract` 每次渲染都会在内存中重注入新版脚本，存量主题自动升级
- 测量脚本保持"仅 fixed 导航产生留白"的既有语义（sticky/静态导航置 0），不扩大范围
- 同构判定要求双方类名非空且完全一致，宁可漏判不误判（漏判时退回现有行为）
- 修复 4（剥离嵌套 host）为可选项，若实施放最后做，不阻塞主问题验证
