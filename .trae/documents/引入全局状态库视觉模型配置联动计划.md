# 引入全局状态库与视觉模型配置联动计划

## Summary
为项目引入客户端全局状态库（Zustand），用于管理「是否已配置视觉模型」这一全局变量；同时提供服务端能力判断，在生成主题/页面时根据该配置决定是否走视觉模型逻辑。未配置视觉模型时，若用户上传参考图片，服务端**跳过图片分析并给出提示**，不阻塞文本生成。

## Current State Analysis
- 视觉模型配置存储在数据库 `prisma.visionConfig`（单行 id=1），另有 `process.env.QWEN_API_KEY` 兜底。
- 服务端视觉封装：[vision-client.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/llm/vision-client.ts) 用模块级缓存 `cachedConfig` 读配置并生成 `ChatOpenAI`；[vision-analyze.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/llm/vision-analyze.ts) 提供 `analyzeImage`。
- 主题生成路由 [themes/generate/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/themes/generate/route.ts) 在收到 `imageId` 时**无条件**调用 `analyzeImage`（try/catch，失败静默回退到仅用文字），没有「未配置视觉模型」的判断。
- 自定义页面生成路由 [pages/generate/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/pages/generate/route.ts) 目前**不含**任何视觉模型逻辑。
- 前端目前**没有**状态管理库，各页面用 `useState` 维护本地状态；视觉配置 UI 在 [personal/page.tsx](file:///d:/frontProjects/agent/smart-blog-agent/src/app/admin/personal/page.tsx)，主题生成对话框在 [theme-generate-dialog.tsx](file:///d:/frontProjects/agent/smart-blog-agent/src/components/admin/theme-generate-dialog.tsx)（含图片上传/发送）。
- 配置读取入口 [vision-config/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/vision-config/route.ts) 的 GET 目前只返回 `baseUrl/model/apiKey`（明文 key），无「是否已配置」布尔。

## Proposed Changes

### 1. 安装依赖：zustand
```powershell
npm install zustand
```

### 2. 服务端：提供「是否已配置视觉模型」判断
文件：`src/lib/llm/vision-client.ts`
- 新增导出 `isVisionConfigured(): boolean`：复用现有 `getVisionConfig()` 缓存，返回 `Boolean(dbConfig?.apiKey || process.env.QWEN_API_KEY)`。
  - 依据：baseUrl/model 均有安全默认值，凭证（apiKey）是决定「能否调用视觉模型」的关键信号；DB 无值时用 env 兜底，与 `createVisionLLM` 的回退逻辑一致。
- 复用现有 `invalidateVisionConfigCache()` 失效机制，配置保存后自动重算。

### 3. 配置接口补充 `configured` 字段
文件：`src/app/api/vision-config/route.ts`（GET）
- 返回体中增加 `configured: boolean`（复用 `isVisionConfigured()`），供前端 store 判断；不改动 PUT 逻辑、不返回额外敏感信息（apiKey 仍仅存在于设置页原有返回中）。

### 4. 客户端全局状态库
新建：`src/lib/store/app-store.ts`（纯 TS，无 React Context，client 组件可安全 import）
- 使用 `create` 创建 Zustand store。
- 状态：
  - `visionConfigured: boolean | null`（null = 尚未加载）
  - `visionLoaded: boolean`
- actions：
  - `setVisionConfigured(value: boolean)`
  - `loadCapabilities()`：fetch `/api/vision-config`，取 `configured` 写入 store（失败时置 `null`，不 crash）。

### 5. 主题生成路由：按配置决定是否走视觉逻辑
文件：`src/app/api/themes/generate/route.ts`
- 在 `imageId` 处理分支前先调用 `isVisionConfigured()`：
  - 已配置 → 保持现状调用 `analyzeImage`，结果拼入 `finalMessage`。
  - 未配置 → 跳过 `analyzeImage`，在 `finalMessage` 前置注「[未配置视觉模型，已忽略所选参考图片的视觉分析]\n」；并在 SSE 流开始后发送一条 `warn` 事件（`send({ type: "warn", message: "未配置视觉模型，已忽略所选参考图片的视觉分析" })`），前端即显示提示。
- 原有 try/catch 回退保留（配置存在但调用失败时仍静默回退，与前一致）。

### 6. 前端：加载全局状态 + 提示
文件：`src/components/admin/theme-generate-dialog.tsx`
- 引入 `app-store` 的 `useAppStore`，在组件挂载（`useEffect`）调用 `loadCapabilities()` 一次。
- 当 `visionConfigured === false` 时，在图片上传区域旁显示一条淡色提示：「未配置视觉模型，上传图片将被忽略」；选择图片仍允许，但发送时服务端会跳过分析（与生成行为一致）。

> 说明：`pages/generate` 目前不含视觉逻辑，本次不改；全局 store 的服务端判断只服务于主题生成的视觉分析路径。若用户目标为「页面生成也接入预览图/视觉分析」，需另行规划，不在本次范围。

## Assumptions & Decisions
- 采用「客户端 Zustand + 服务端判断」组合（用户已确认）。
- 未配置视觉模型时的行为为「跳过并提示」，不阻断生成（用户已确认）。
- 全局变量本次仅「是否已配置视觉模型」（用户已确认）。
- 「已配置」判定依据凭证（apiKey，DB 或 env 兜底），baseUrl/model 有默认值不计入配置与否。
- 主题生成是唯一会调用视觉模型的路径；`pages/generate` 无相关逻辑，不改。
- Zustand store 属于全局共享但仅客户端使用；不在 `layout.tsx` 做全局初始化，而是由使用方（生成对话框）在挂载时懒加载，避免增加额外请求。
