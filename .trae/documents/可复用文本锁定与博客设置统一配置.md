# 可复用文本：主题配置只读 + 博客设置统一配置

## 需求概述
当主题配置中的某个文本字段被"保存为可复用"（`source: "reusable-text"`）后：
- 该字段在主题配置里**不再可修改**（只读展示），避免各主题误改造成共享值漂移。
- 该字段统一由**博客设置**页面集中配置。

## 现状分析
1. **可复用文本库**：`src/lib/reusable-text.ts`，存于 `SiteConfig.textLibrary`（`key → string`）。
   - API：`src/app/api/reusable-text/route.ts` — `GET` 返回全量库；`POST` 支持 `{key,text}` 新增/更新 与 `{key,action:"delete"}` 删除。
2. **主题配置对话框** `src/components/admin/content-editor-dialog.tsx`：
   - `globalTextFields`（`source==="global"`）：已只读展示 + "来自博客设置"徽标 + "前往修改"链接 → `/admin/settings`。
   - `themeTextFields`（`source!=="global" && !==="readonly"`，即 `"theme" / undefined / "reusable-text"`）：全部可编辑。
   - `source==="reusable-text"`（`bound`）字段：显示"解除"按钮、提示"编辑将同步所有绑定字段"，且 Input 可编辑（`updateTextField` 会通过 `upsertText` 同步回文本库）。
   - 未绑定字段的三种操作保留：存在同名库条目→"绑定可复用文本"；无条目→"保存为可复用"；另有"新增可复用文本"。
3. **博客设置页** `src/app/admin/settings/page.tsx`：仅管理 `GLOBAL_FIELDS`（`FIELD_DEFINITIONS` 中非只读、`EDITABLE_KEYS`），通过 `/api/site-config` PUT 保存到 `SiteConfig.config`。**当前没有可复用文本（`textLibrary`）的编辑入口**。
4. **渲染** `content-renderer.ts#resolveTextValue`：`reusable-text` 字段取值优先级 文本库(`texts[textKey]`) → `field.value`（兜底）。

## 需要澄清的决策点
- 可复用文本在博客设置中以**独立区块**展示（与现有全局字段分开），因为其存储（`textLibrary`）与博客设置主配置（`config`）是两个独立字段。在 Plan 阶段保留此决策，勿合并进现有全局字段表单。

## 改动方案

### 1. 主题配置对话框：可复用字段只读化
文件：`src/components/admin/content-editor-dialog.tsx`

**位置**：`themeTextFields` 渲染块（约 L375-454）中对 `bound` 字段的处理。

- 将 `bound`（`source==="reusable-text"`）字段改为只读展示，类似 `globalTextFields` 区块：
  - 顶部右侧仍是 `bound` 的**"解除"**按钮（保留解除能力，点击走 `unbindTextField`，回退到主题本地值）。
  - 去掉可编辑的 `<Input>`，改为只读文本展示 `effValue`（沿用现有 `texts[tf.textKey] ?? tf.value` 兜底逻辑）。
  - 徽标提示改为："复用于可复用文本库 · 在博客设置中统一编辑"。
  - 增加"前往修改"链接（复用现有 `<Link href="/admin/settings">` 样式），跳转博客设置。
- 未绑定字段（`!bound`）：交互保持不变（编辑 Input、"保存为可复用"/"绑定可复用文本"、"引用可复用文本…"下拉）。
- 防御性改动：`updateTextField` 的守卫由 `if (!field || field.source === "global") return` 增补为 `|| field.source === "reusable-text"`，确保即使有入口也不会从主题侧修改文本库（不新增此入口亦可，但保留守卫以防回归）。

### 2. 博客设置页：新增可复用文本管理区块
文件：`src/app/admin/settings/page.tsx`

在现有全局字段（`editableEntries`）之后、站点统计只读区之前，新增"可复用文本（共享配置）"区块：

- **加载**：进入页面时并行请求 `/api/reusable-text`，得到 `Record<string,string>`，存入本地 state `reuseTexts`。
- **展示与编辑**：对每条 `[key, text]` 渲染一行（沿用现有样式）：左侧显示 `key`（若 `FIELD_DEFINITIONS[key]` 存在则显示其 label，否则显示 key，并保留小字备注原始 key），右侧为可编辑值（`<Input>` 或保留原按钮布局内）。底部提供"新增可复用文本"（复用 Key+内容输入，提交 `POST /api/reusable-text`）。
- **保存**：完成编辑后，点击保存时对每条更新过的条目调用 `POST /api/reusable-text {key, text}`；被移除的条目调用 `POST /api/reusable-text {key, action:"delete"}`。保存成功回显"已保存"提示。
  - 为避免与现有全局字段共用 flow，复用文本的保存**独立**处理（不经 `/api/site-config` PUT），不影响现有 `persistConfig`。
  - 简单实现：为每个条目维护本地方值，保存时 diff 并分别 upsert；支持删除按钮。
- 若库为空，显示空状态文案"暂无可复用文本，可在主题配置中保存字段为可复用文本后到这里统一编辑"。

> 说明：为控制范围，本方案新建"可复用文本"独立状态与保存逻辑，不改动现有全局字段的加载/保存代码、字段注册表或数据库结构。

## 假设与决策
- 可复用文本以**独立区块**加入博客设置（存储字段 `textLibrary` 与 `config` 相互独立）。
- 主题配置中仅对**已绑定**可复用文本的字段做只读化；未绑定字段行为不变。
- 保留主题配置中的"解除"（解除绑定回退主题本地）与"保存为可复用"/"新增可复用文本"入口。
- 文本库 key 沿用字段 key，不被修改；博客设置里若 key 命中 `FIELD_DEFINITIONS` 则显示中文 label 便于识别。
- 不做数据库结构变更、不做全局迁移脚本、不改渲染取值优先级。

## 验证步骤
1. 主题配置：将某文本字段"保存为可复用"→ 该字段立即变为只读、显示"在博客设置中统一编辑"与"前往修改"链接，仍有"解除"按钮。
2. 主题配置："解除"后又恢复可编辑；"新增可复用文本"/"引用可复用文本"仍可用。
3. 博客设置 `/admin/settings`：新增区块列出全部可复用文本，可编辑值、新增、删除，保存后刷新仍生效。
4. 渲染：某主题绑定可复用文本字段后，博客设置中修改该值，前端 `/blog`、`/blog/archive` 等页面使用该字段处同步更新。
5. `npm test`（当前 108 通过）与主题配置、博客设置保存接口（`PATCH /api/themes/[id]`、`PUT /api/site-config`、`POST /api/reusable-text`）回归。
