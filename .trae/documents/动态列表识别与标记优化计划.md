# 动态列表识别与标记优化计划（新生成主题）

## 摘要

首页「精选文章/近期文章」等信息当前**有时**没有从文章列表取数据。根因不是渲染逻辑缺失（`dynamic-articles` 运行时本就会用数据库文章填充），而是**生成阶段 LLM 偶尔未把这类『文章列表/卡片网格』区块标记为 `dynamic-articles`**，反被内容提取器当成普通文本（`data-content="text"`）打标，导致标题/摘要变成静态可编辑文本而非动态列表。

用户诉求有两条：
1. 不止「精选文章」，**所有可识别为列表/动态内容**的区块都应被标记为动态内容（文章列表→`dynamic-articles`，标签→`dynamic-tags`，分类→`dynamic-categories`，导航→`nav-list`），静态文本才用 `text`。
2. **仅对『新生成主题』生效**（不修正历史主题，不改运行时渲染）。

因此改动聚焦在生成管线：**① 强化生成提示词的动态内容识别规则；② 在生成时校验阶段增加兜底识别**（校验失败会自动驱动 LLM 修订，形成闭环）。

## 现状分析

关键文件与机制：

- [theme-agent.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-agent.ts)
  - `DYNAMIC_ARTICLES_RULE`（L144-147）：规定文章列表用 `data-content="article-list" data-content-type="dynamic-articles"`。
  - `DYNAMIC_TAG_RULE`（L150-152）：规定标签云/分类列表用 `dynamic-tags` / `dynamic-categories`。
  - `PAGE_SPEC.home.bodyPrompt`（L202-210）与 `PAGE_SPEC.list.bodyPrompt`（L214-220）：注入上述两条规则，但它们只针对「文章列表/标签云」两个场景，没有给出**『先判断动态还是静态』的统一决策规则**，也未覆盖「精选/热门/推荐阅读」「文章卡片网格」等多种文章列表形态 → LLM 容易把文章卡片区的标题/摘要当 `text` 处理。
  - `buildPageSystemPrompt` 的 `【内容标记规则】`（L275-279）：同样只笼统说「动态内容区域（文章列表等）」，对「如何识别文章列表」指导不足。
- [content-renderer.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/content-renderer.ts#L716-L734)：`dynamic-articles` 渲染时已从 `dynamicData.articles` 取真实文章填充，无需改动。
- [content-extractor.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/content-extractor.ts#L245)：对未打标文本自动补 `data-content="text"`（兜底），会把漏标的文章标题/摘要变成静态文本 → 这是「精选文章变成静态信息」的直接成因。
- [theme-splitter.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/theme-splitter.ts#L292) `validatePageFragment`：生成期校验，当前只查「文本覆盖率/类名重叠」，未查「漏标的文章列表」。
- [theme-graph.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-graph.ts#L406) `makeValidatorNode`：校验不通过会产出 `feedback`，在 [L365](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-graph.ts#L365) `makePageNode` 中被回传驱动 LLM 修订 → 因此在 `validatePageFragment` 里加「漏标文章列表」检查可自动触发修订闭环。

## 拟改动

### 改动 1：theme-agent.ts —— 新增统一「动态内容识别规则」并接入各提示词（必做，低风险）

在 [theme-agent.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-agent.ts) 中新增一个常量 `DYNAMIC_CONTENT_RULE`（放在 `DYNAMIC_TAG_RULE` 之后，L152 附近），内容为一份「先判动态/静态」的分类决策规则：

```ts
/** 动态内容识别规则：统一指导 LLM 判断区块属于动态列表还是静态文本。 */
const DYNAMIC_CONTENT_RULE = `【动态内容识别规则】生成页面时，先判断每个区块属于「动态列表」还是「静态文本」：

一、动态列表（运行时会自动填充真实数据，禁止手写占位条目、禁止硬编码链接）：
1. 文章类列表：任何「展示多篇文章 / 多个卡片 / 网格」的区块（如 精选文章、热门文章、近期/最新文章、推荐阅读、文章卡片、文章网格）都归为此类，整块只用一个外层容器标记：
   <section data-content="article-list" data-content-type="dynamic-articles">
     首个子元素是单个文章项模板（<article> 或 <li>），模板内用 data-map 标记 title、excerpt、date、category、link；封面用 <img data-map="cover">（仅限网格/多列卡片容器内）。
   </section>
   切勿给每个文章项的标题/摘要/日期单独打 data-content="text"——整块就是一个动态列表。
2. 标签/分类列表：标签云、标签/分类导航、筛选行 → 分别用 data-content-type="dynamic-tags" / "dynamic-categories"（模板项内 data-map="name" 标记名称、data-map="link" 标记链接）。
3. 导航/页脚链接列表 → data-content-type="nav-list"。

二、静态文本（单条内容，运行时按后台配置替换）：区块标题、段落、统计数字、时间线条目、作者介绍等 → data-content + data-content-type="text"。

【识别要点】同标签、同 class、含文章链接、>1 个的重复结构即为文章列表；不要把重复文章卡片拆成多条 text，不要硬编码文章标题或链接。`
```

接入位置：
- `PAGE_SPEC.home.bodyPrompt`（L202-210）：在 `${DYNAMIC_ARTICLES_RULE}` 之前插入 `${DYNAMIC_CONTENT_RULE}`。
- `PAGE_SPEC.list.bodyPrompt`（L214-220）：同样在最前插入 `${DYNAMIC_CONTENT_RULE}`。
- `buildPageSystemPrompt` 的 `【内容标记规则】`（L275-279）：在首句「动态内容区域（文章列表等）必须使用 data-content…」处补一句引用动态识别判定，并把「如何识别文章列表」的要点压缩进该段，例如在该段末尾追加：
  `判断某个区块是动态列表还是静态文本，遵循上述【动态内容识别规则】：重复的含文章链接卡片/网格结构应整体标记为 dynamic-articles，切勿拆成多个 text 字段。`

说明：保留现有 `DYNAMIC_ARTICLES_RULE` / `DYNAMIC_TAG_RULE` 不加改动（它们是具体的绑定格式），新增的 `DYNAMIC_CONTENT_RULE` 负责「分类决策」，两者互补共存，避免大改既有格式化规则而导致回归。

### 改动 2：theme-splitter.ts —— 生成期校验新增「漏标文章列表」检查（建议做，自动驱动修订）

在 [theme-splitter.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/theme-splitter.ts) 的 `validatePageFragment`（L292）中，追加一个保守检测：扫描页面片段中「未标记动态文章列表」的文章卡片簇。

新增私有函数，例如：

```ts
/** 探测未标记 dynamic-articles 的文章卡片簇（同标签+同 class+含文章链接，>=2 项，且不在动态容器/正文占位/导航内）。 */
function detectUnmarkedArticleList(doc: Document): boolean {
  const isInsideDynamic = (el: Element) =>
    el.closest('[data-content-type^="dynamic-"], [data-content-type="article-body"], [data-map="body"], nav, footer') !== null
  const hosts = [
    ...doc.querySelectorAll('article, li, [class*="post"], [class*="card"], [class*="grid"] > *'),
  ]
  // 按父元素聚合出“重复结构”的卡片簇，再判定是否含 /blog/ 文章链接
  const groups = new Map<Element, Element[]>() // 父级 -> 重复子项
  for (const el of hosts) {
    if (isInsideDynamic(el)) continue
    if (!el.querySelector('a[href*="/blog/"]')) continue
    const parent = el.parentElement
    if (!parent) continue
    const list = groups.get(parent) ?? []
    list.push(el)
    groups.set(parent, list)
  }
  for (const [, items] of groups) {
    if (items.length >= 2 && items.every((it) => it.tagName === items[0].tagName)) {
      return true
    }
  }
  return false
}
```

在 `validatePageFragment` 中找到「内容标记覆盖率」检查（L321-342）之后，加入：

```ts
if (detectUnmarkedArticleList(doc)) {
  issues.push('页面存在未标记为动态文章列表的重复文章卡片/网格：这类区块应整体标记为 <section data-content="article-list" data-content-type="dynamic-articles">，并把卡片作为模板项用 data-map 标字段（title/excerpt/date/category/link），而非把标题摘要当 text。')
}
```

作用：该 issue 会令 `validate ok=false` → [makeValidatorNode](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-graph.ts#L406) 产出反馈 → [makePageNode](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-graph.ts#L365) 下一轮修订时携带该反馈让 LLM 改正标记，形成「生成时误标 → 自动识别 → 修订纠正」闭环。

保守性说明：只对「≥2 个同标签、同 class、含 `/blog/` 链接、且不在动态容器/正文/导航内」的重复结构报错，最大限度避免误伤装饰性卡片或导航，降低无条件修订循环风险。

## 假设与决策

- **不改运行时渲染**（content-renderer.ts / content-extractor.ts 对已有主题的兼容保持不变），因此历史主题、SPA 前台行为不受影响。
- **不改数据层与 DB**（`article-list` 取数逻辑 `HOME_PAGE_ARTICLE_LIMIT` 等维持现状，首页动态列表已能取文章）。
- 仅影响**新生成主题**；已保存主题不重写、不迁移。
- 保留现有 `DYNAMIC_ARTICLES_RULE` / `DYNAMIC_TAG_RULE` 原样（格式化规则），新增 `DYNAMIC_CONTENT_RULE` 负责「战策判定」，降低回归风险。
- 校验兜底采用**保守启发式**，只报告高置信度的文章卡片簇，避免误报引发空转修订。
