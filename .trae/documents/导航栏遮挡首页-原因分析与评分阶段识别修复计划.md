# 导航栏遮挡首页：原因分析与修复计划（含评分阶段识别）

## 一、Summary（目标）

当前激活主题的**首页（/blog）首屏被固定导航栏遮挡**。本计划：

1. 定位根因并给出渲染管线修复，让任意存量/新主题的首页都不再被固定导航遮挡。
2. **在评分（audit 静态审计 + judge LLM 评分）阶段就识别出该类问题**，使生成阶段能自动检出并修订，而非只靠运行时观察。

## 二、Current State Analysis（现状分析 + 实测证据）

实测 `/blog`（dev server :3000，只读抓取渲染后 HTML 用 JSDOM 计算样式）：

| 检查项 | 实测值 | 说明 |
| --- | --- | --- |
| 导航 | `NAV0 NAV.main-nav pos=fixed` | 导航是**固定**定位（`.main-nav`，`position: fixed`）|
| `body padding-top` | `0px` | body 没有顶部留白 |
| `[data-page-host]` padding-top | `0px` | host 也没有顶部留白 |
| CSS 是否声明 `--nav-h` | `true` | `:root` 已定义 `--nav-h` |
| CSS 是否有 `body{padding...var(--nav-h)}` | `false` | **骨架漏写 body 级留白** |

相关代码链：

- [blog.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/blog.ts#L178-L180) `renderBlogTheme`：`mergeThemePage(layout, pageHtml, { navClearance: pageType !== "home" })` —— **首页被显式排除** `navClearance`。
- [theme-splitter.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/theme-splitter.ts#L162-L166) `mergeThemePage`：`if (options?.navClearance && !hasBodyNavClearance(doc)) host.style.paddingTop = "var(--nav-h, 0px)"` —— 只有非 home 页且 body 未自留白时才补 host 留白。
- [theme-splitter.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/theme-splitter.ts#L127-L138) `ensureLayoutContract` 运行时脚本：把 `--nav-h` 刷新为 fixed 导航的实际高度（非 fixed 为 0）。
- [theme-agent.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-agent.ts#L163) 骨架契约：要求 `:root` 定义 `--nav-h`，且"正文将由布局（body）读取该变量自动让位"，`.data-page-host` 自身不应写 padding-top。

## 三、Root Cause（根因）

两处叠加导致首页首屏被遮挡：

1. **骨架漏写 body 级留白**：主题定义了 `--nav-h` 也用了 `position: fixed` 导航，但**没有**写 `body { padding-top: var(--nav-h) }`（`hasBodyNavClearance === false`），违反骨架契约（L163）。
2. **home 页被渲染端显式排除补丁**：`navClearance: pageType !== "home"`。非 home 页靠 `mergeThemePage` 补 host `padding-top` 兜底，而 home 页既不补 host、body 又没留白 → 固定导航直接叠盖首屏。

类比：非 home 页因 host 补丁侥幸正常，把"让位"完全押在 body 级留白上——骨架一旦漏写就只在 home 暴露。

## 四、Proposed Changes（改动方案）

### 修复 1（主，渲染兜底）：`mergeThemePage` 对所有页面统一 host 留白

文件：[theme-splitter.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/theme-splitter.ts#L162-L166)

去掉 `options?.navClearance` 门控，只保留 body 已自留白判断：

```ts
host.innerHTML = pageHtml
// 布局自身已在 body 上提供 var(--nav-h) 级留白时不再叠加 host 留白（避免双重间距）；
// 否则所有页面（含 home）统一补 padding-top:var(--nav-h,0px)。
if (!hasBodyNavClearance(doc)) {
  host.style.paddingTop = "var(--nav-h, 0px)"
}
```

- **为什么安全**：`--nav-h` 由运行时脚本按"是否 fixed"计算，非 fixed 导航时为 `0`，此时 `padding-top: 0` **无副作用**；只有固定导航才产生真实留白。符合既有"仅固定导航需要留白"契约。
- **一次覆盖**：home / list / detail / custom 全部页面，不再有 home 特例；骨架漏写 body 留白时也能兜底。
- `navClearance` 参数保留（向后兼容，调用方无需改动，变为无效开关）。

### 修复 2（一致性，客户端预览）：`injectPageIntoLayout` 同样统一留白

文件：[layout-inject.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/layout-inject.ts#L10-L16)

纯字符串路径（客户端 bundle，避免引入 jsdom），镜像修复 1：

```ts
const hasBodyClearance = /(?:html\s*,\s*body|body)\s*\{[^}]*padding[^}]*var\(--nav-h/i.test(layoutHtml)
const style = !hasBodyClearance ? ' style="padding-top:var(--nav-h,0px)"' : ""
```

- 使后台各页类型（含 home）预览与线上渲染一致，不再出现"预览被遮挡/线上正常"的偏差。
- `navClearance` 参数保留兼容。

### 修复 3（评分识别·静态审计）：`analyzeSkeletonStyles` 新增"固定导航无留白"规则

文件：[style-analyzer.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/style-analyzer.ts#L250-L304)

在 `analyzeSkeletonStyles` 的 CSS 分支内新增纯 CSS 规则检查（复用现有 `parseRuleBlocks` / `collectRootVars`）：

- `hasFixedNav(css)`：存在选择器命中 `nav` / `header`（标签或含 `nav` 的类，如 `.main-nav`、`.navbar`）且对应规则块内 `position: fixed`。
- `hasBodyTopClearance(css)`：存在 `body` / `html,body` 规则块，其 `padding`/`margin` 顶部声明引用 `var(--nav-h)`（与 `hasBodyNavClearance` 同一判定）。
- 若 `hasFixedNav && !hasBodyTopClearance` → 追加 **skeletonIssue（error 级）**：
  `固定导航（position:fixed）未在 body 上声明 padding-top:var(--nav-h)，首页首屏会被导航遮挡；请在 :root 定义后增加 body{padding-top:var(--nav-h)}`

**机制**：error 级 skeletonIssue 会命中 [theme-graph.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-graph.ts#L480-L483) 的 `computeRevisePlan` → `skeletonFix = true` → 触发**骨架级修订/整树重建**，让 LLM 补上 body 留白。因此该类问题在**生成/评分阶段**（audit 早于 judge）即可自动检出并修订，不依赖运行时可观察性。

### 修复 4（评分识别·LLM judge）：`JUDGE_SYSTEM_PROMPT` 补充 layout 维度排查项

文件：[theme-graph.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/agents/theme-graph.ts#L527-L530)

在"重点排查"追加一条（对应 `layout` 维度）：

`固定/吸顶导航必须为页面预留空间（导航 position:fixed 时 body 需有 padding-top 引用 var(--nav-h)，数据源/首屏不得被导航遮挡）。命中请在 layout/issues 给出可执行建议并拉低 layout 分。`

## 五、Assumptions & Decisions（假设与决策）

- **渲染兜底 + 评分识别并存**：修复 1/2 是运行时兜底（存量/自定义主题不重新生成也能恢复）；修复 3/4 让新生成主题在评分阶段自纠，不再依赖兜底。二者互补。
- 审计规则定为 **error**（非 warn），以驱动骨架级修订；渲染端兜底保证即使规则漏过也不会线上破相。
- 统一 host/预览留白对**非 fixed 导航无副作用**（`--nav-h=0`），维持"仅固定导航留白"既有语义；**不处理**"透明导航叠 hero 的创意设计"（本契约明确固定导航需让位，见 theme-agent L163）。
- 不改 DB 存量主题数据；存量主题下次 `mergeThemePage` 渲染自动生效。
