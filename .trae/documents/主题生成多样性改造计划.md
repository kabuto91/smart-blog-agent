# 主题生成多样性改造计划（随机设计种子 + 放宽后处理约束）

## 一、总结

当前主题生成链路每次产出样式雷同，根因是**生成侧缺乏随机性引导**与**后处理一刀切削平**叠加：所有主题都被压向"紧凑精致、同一套类名骨架、同一节奏"的安全形态。本计划做两处改造：

1. **随机设计种子**：planner 阶段从设计原型池（美学/布局/配色/排版/节奏）随机抽取组合注入简报，避免 LLM 每次选"安全答案"。
2. **放宽后处理约束**：`normalizeThemeSpacing` 按选择器分级 clamp——hero/feature 等视觉大区块允许大间距大字号，普通区块维持现有上限；同步放宽骨架 prompt 中的硬性间距数字。

不动的部分：`ensureLayoutContract` 溢出安全兜底 CSS、validator/audit/judge 修订循环、LLM temperature。

## 二、现状分析（雷同根因）

### 生成侧（收敛）

- [theme-agent.ts](d:\frontProjects\agent\smart-blog-agent\src\agents\theme-agent.ts#L66-L98) `SKELETON_SYSTEM_PROMPT` 规定了**固定类名清单**（.container/.section/.post-card/.btn/.sidebar/.article-header…），每次生成都基于同一套类名结构"换皮"。
- 同一 prompt 中【间距规范】硬性规定"section padding 24~40px 不超 48px、整体紧凑精致"——所有主题节奏统一。
- [theme-graph.ts](d:\frontProjects\agent\smart-blog-agent\src\agents\theme-graph.ts#L228-L261) `generateDesignBrief` 只让 LLM 自由提炼风格，无随机性引导，LLM 倾向反复选"极简杂志风"等高频答案；前端 4 个预设（theme-generate-dialog.tsx）进一步收敛用户输入。
- 页面阶段被强制"只能使用骨架已有类名，禁止自创"（buildPagePromptContext 硬性约束），页面布局被骨架类库锁死（此项本次不动，属用户未选方向）。

### 后处理侧（削平）

- [theme-splitter.ts](d:\frontProjects\agent\smart-blog-agent\src\lib\theme\theme-splitter.ts#L362-L471) `normalizeThemeSpacing` 一刀切 clamp：所有匹配 section/hero/footer 的块 padding ≤60px、margin ≤64px、gap ≤32px、h1 ≤40px / h2 ≤34px / h3 ≤28px。**hero 大留白、超大展示标题等设计意图全部被削平**——即使 LLM 抽风生成了大胆排版，落库前也被压回同一种节奏。
- prompt 间距规范与 clamp 上限互相强化，形成双重收敛。

### 结论

"区块太固定"的感受 = 固定类名骨架（结构层）+ 无随机风格引导（方向层）+ 一刀切 clamp（表现层）。本次改造针对方向层与表现层。

## 三、改动方案

### 改动 1：随机设计种子（planner 注入）

**文件：`src/agents/theme-agent.ts`**

新增导出常量 `DESIGN_SEED_POOLS` 与函数 `rollDesignSeeds()`：

```ts
export interface DesignSeeds {
  aesthetic: string   // 美学方向
  layout: string      // 布局原型
  palette: string     // 配色策略
  typography: string  // 标题排版
  rhythm: "compact" | "balanced" | "airy"  // 节奏档位
}
```

- 池子内容（每池 6~10 项，中文描述，如）：
  - aesthetic：瑞士国际主义 / Brutalism 粗野主义 / 玻璃拟态 / 暗色极客终端 / 纸墨书法 / Zine 拼贴 / 孟菲斯几何 / 报刊印刷 / 北欧极简 / 赛博霓虹 / 新艺术装饰 / 蓝图工程风…
  - layout：顶部导航+居中单栏 / 顶部导航+双栏（正文+侧边）/ 左侧竖排导航+右内容 / 杂志多栏网格 / 全宽卡片纵列流 / 紧凑列表无卡片…
  - palette：高对比单色+锐利点缀 / 低饱和柔和 / 深色底+荧光强调 / 双色调 / 大胆撞色互补 / 暖调大地色…
  - typography：超大展示型标题（clamp 可到 72px+）/ 衬线标题×无衬线正文对比 / 等宽字体系统 / 细字重大留白…
  - rhythm 三档决定 prompt 中的间距指引与 clamp 联动文案。
- `rollDesignSeeds()` 用 `Math.random()` 每池独立抽取（无需种子回放）。

**文件：`src/agents/theme-graph.ts`**

- `makePlannerNode` 中先 `rollDesignSeeds()`，把种子作为参数传入 `generateDesignBrief`。
- `generateDesignBrief` 的 HumanMessage 追加一段：

```
【随机设计方向种子】
本次必须以此组合为基础展开细化（仅当用户需求中已明确指定某维度的方向时，才用用户的覆盖对应维度，其余维度必须遵循种子）：
美学方向：{aesthetic}
布局原型：{layout}
配色策略：{palette}
标题排版：{typography}
节奏档位：{rhythm 对应描述}
```

- brief 解析后把节奏档位以一行文本写入 brief（如 `节奏：大留白呼吸感`），随 designBrief 自然流入 skeleton/page 节点的 prompt（现有机制已把 designBrief 拼进各节点 userContent，无需额外 state 字段）。

**文件：`src/agents/theme-agent.ts` `SKELETON_SYSTEM_PROMPT` 间距规范同步改**

现有硬性数字（24~40px 不超 48px）改为按节奏分档指引：

```
【间距与节奏】
根据设计简报中的节奏档位决定间距体系，三档参考：
- 紧凑（compact）：section padding 20~36px，gap 12~20px，信息密集；
- 均衡（balanced）：section padding 32~56px，gap 16~28px；
- 大留白（airy）：section padding 64~110px，hero 区可到 120px，gap 24~40px，强调呼吸感。
同档内保持一致，禁止跨档混用；hero/banner 类视觉大区块可在档位基础上再放大约 1.5 倍。
```

### 改动 2：放宽后处理 clamp（分级限额）

**文件：`src/lib/theme/theme-splitter.ts`**

`clampCssSpacing` 改为按选择器分级：

1. 新增 hero 判定正则（在现有 isTarget 基础上细分）：

```
hero 选择器：/(?:^|[\s,>+~(])(?:\.hero|\.banner|\.feature|\.cover|\.jumbotron|\.masthead)(?:$|[\s,.:#\[{>~+)])/i
```

2. 限额表由单一 `SPACING_LIMITS` 拆为两张：

| 属性 | 普通区块（现值不变） | hero 类区块 |
|---|---|---|
| padding / padding-top / padding-bottom | 60 | 120 |
| margin / margin-top / margin-bottom | 64 | 96 |
| gap | 32 | 48 |

3. 标题字号 `HEADING_FONT_LIMITS` 拆为两级：
   - 全局：h1 40→56、h2 34→40、h3 28→32
   - 选择器含 hero 类（或选择器本身是 hero 内标题，如 `.hero h1`）：h1 80、h2 56、h3 40
4. 宽度 clamp（px>1400 / vw>100 → 100%）**保持不动**（防横向溢出的关键兜底）。
5. `THEME_SAFETY_CSS`、`ensureLayoutContract`、`CLASS_BRIDGE`、`sanitizePageFragment` 均不动。

漏识别风险：LLM 用了未收录的 hero 类名（如 .welcome）→ 按普通限额保守 clamp，只是不放大、不破坏，可接受。

**文件：`src/lib/theme/theme-splitter.test.ts`**

- 新增用例：hero 选择器 140px padding 不被削平；`.hero h1 { font-size: 72px }` 保留；普通 `section { padding: 90px }` 仍 clamp 到 60；`section h1 { font-size: 60px }` clamp 到 56。
- 修正受现有上限值影响的旧断言。

## 四、假设与决策

- 随机种子只在**全新生成**（非 iteration）时注入；迭代模式 planner 直接跳过，不受影响。
- 用户明确写了风格（如"日式侘寂"）时以用户为准，种子只补齐未指定的维度——由 planner prompt 措辞保证，不做关键词检测（避免过度工程）。
- clamp 与节奏档位**不做运行时联动**（不把 seeds 传进 normalizeThemeSpacing），采用固定的 hero/普通两级分类，简单且漏识别不破坏。
- 不改 temperature、不改"页面只能用骨架类名"约束、不动 judge/audit 循环（用户未选）。

## 五、验证步骤

1. `npx vitest run src/lib/theme/theme-splitter.test.ts` — clamp 分级单测通过。
2. `npx vitest run`（或项目现有测试命令）— 全量回归，确认 theme-agent/theme-graph 相关测试不受影响（若有 planner 快照类断言需同步更新）。
3. `npm run build`（或 `npx tsc --noEmit`）— 类型检查通过。
4. 手动验证：启动开发服务器，在主题生成对话框用**同一句泛化需求**（如"帮我生成一个博客主题"）连续生成 3 次，对比三次骨架：美学方向、布局原型、hero 间距/标题字号应有可感知差异；再用"极简杂志风"明确指定生成 1 次，确认仍尊重用户指定风格且无溢出（横向不出现滚动条）。
