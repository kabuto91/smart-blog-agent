# 全局动态参数库（跨主题复用动态参数）实现计划

## Summary

新增站点级「全局动态参数库」，让用户在一个主题里自由定义/添加的动态参数（动态列表 `dynamic-list` 等）能存到库中，并被其他主题中具有**相同 `data-content` 字段键**的动态字段复用。复用机制沿用现有文本字段 `source:"global"` / `globalKey` 的既有模式（见 [site-config.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/site-config.ts)、[field-registry.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/field-registry.ts)）。

核心思路：库中保存动态字段的「定义 + 可编辑数据」（`type`/`label`/`itemTemplate`/`fieldMapping`/`items`）并按 `data-content` 键存储；主题内某动态字段若显式「绑定到全局」，渲染时使用库里的定义与 items（共享、一处编辑处处生效），原理与文本 `GLOBAL_FIELDS` 一致但针对动态字段。

## 当前状态分析

- 动态字段类型见 [content-config.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/types/content-config.ts#L9-L24)：`dynamic-articles/categories/tags`、`article-body`、`dynamic-list`。
- 编辑器中「动态数据（从文章管理自动获取）」与「自定义列表」区块在 [content-editor-dialog.tsx](file:///d:/frontProjects/agent/smart-blog-agent/src/components/admin/content-editor-dialog.tsx#L354-L435)：前者只读，后者是主题**本地**维护 items，目前无跨主题共享概念。
- 渲染走 [content-renderer.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/content-renderer.ts#L636-L741)：`renderDynamicField` 内对 `dynamic-list` 走 `renderCustomListField`（用 `field.items`/`fieldMapping`/`itemTemplate`）；`dynamic-articles/tags/categories` 走系统数据。
- 渲染入口：主渲染 [blog.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/blog.ts#L170-L184)、预览 [themes/render/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/themes/render/route.ts#L43)、自定义页 [pages/generate/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/pages/generate/route.ts#L123-L130)。三者都 `getSiteConfig()` 后调 `renderContent`。
- 存储层：`SiteConfig` 表以 JSON `config` 存站点级文本配置（[schema.prisma](file:///d:/frontProjects/agent/smart-blog-agent/prisma/schema.prisma#L10-L15)）。可加一列承载动态参数库，无需新建表。

## 目标交互（决策）

1. 编辑器「动态数据/自定义列表」区块顶部加按钮「**+ 新增动态参数入库**」：弹出表单，自由填写 `名称`、`字段键`、`类型`、`label`、`itemTemplate`、`fieldMapping`、可选 `items`，保存到全局库。
2. 对主题内已有动态字段：
   - 若其键已在库中且未绑定：显示提示「检测到全局参数库同名字段」，提供「**绑定到全局**」按钮。
   - 绑定后：字段显示徽章「来自全局参数库 · 名称」与「**解除绑定**」，其 items/定义编辑落到**库**（共享），不在主题本地。
   - 若不在库中：提供「**→ 加入全局参数库**」按钮（把该字段的当前定义/数据复制进库并可选直接绑定）。
3. 渲染复用：主题字段 `source:"global"`（含 `globalKey`）时，渲染取库中该键的定义与 items；未绑定时用主题本地值。绑定选择持久化在主题 `contentConfig` 的字段上（随 onSave 保存），与文本全局字段行为一致。

## 提议改动（按文件）

### 1. 存储/数据层
- **[prisma/schema.prisma](file:///d:/frontProjects/agent/smart-blog-agent/prisma/schema.prisma#L10-L15)**：`SiteConfig` 增加 `dynamicConfig String @default("{}") @map("dynamic_config")`。运行 `npx prisma migrate dev` 生成迁移（或 `db push`）。
- **新增 `src/lib/global-dynamic.ts`**：
  - 导出类型 `GlobalDynamicFieldMeta`（`name, type, label, itemTemplate, fieldMapping, items?`）。
  - `getGlobalDynamic(): Promise<Record<string, GlobalDynamicFieldMeta>>`：读 `SiteConfig.dynamicConfig` JSON（异常兜底返回 `{}`）。
  - `saveGlobalDynamic(lib: Record<string, GlobalDynamicFieldMeta>): Promise<void>`：写回 `dynamicConfig`（黑白名单只存本库字段，避免残留）。
  - 提供 `upsertGlobalDynamic(key, meta)` / `deleteGlobalDynamic(key)` 便捷函数。

### 2. 类型
- **[content-config.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/types/content-config.ts#L18-L24)**：`DynamicField` 增加 `source?: "theme" | "global"` 与 `globalKey?: string`（对齐 `TextField`）。
- **新增导出** `GlobalDynamicFieldMeta` 类型（可放在 global-dynamic.ts，content-renderer 引用）。

### 3. 渲染（复用）
- **[content-renderer.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/lib/theme/content-renderer.ts#L636-L741)**：
  - `renderDynamicField` 增加入参 `globalDynamic?: Record<string, GlobalDynamicFieldMeta>`。
  - 对 `dynamic-list`：若 `field.source === "global"` 且 `globalDynamic[field.key]` 存在，则用 `globalDynamic[field.key]` 的 `items`/`fieldMapping`/`itemTemplate` 渲染（一次性合并到本地变量，不写回源数据，保证共享项实时生效）。其余类型 `dynamic-articles/tags/categories` 仍走系统数据。
  - `renderContent` 透传该入参（默认 `{}`）。
- **`src/lib/blog.ts`** 主渲染（L170-L184）、**[themes/render/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/themes/render/route.ts)**、**[pages/generate/route.ts](file:///d:/frontProjects/agent/smart-blog-agent/src/app/api/pages/generate/route.ts)**：调用 `renderContent` 前 `const lib = await getGlobalDynamic()` 传入。仅须这三处与渲染路径相关调用点。

### 4. 管理 API
- **新增 `src/app/api/global-dynamic/route.ts`**：
  - `GET`：返回全库 `Record<string, GlobalDynamicFieldMeta>`。
  - `POST`：body `{ key, meta }` 或 `{ key, patch }`，upsert 后返回全库。
  - `DELETE`：body `{ key }`，删除后返回全库。
  - 复用仓库内既有 API 风格与鉴权约定。

### 5. 编辑器 UI
- **[content-editor-dialog.tsx](file:///d:/frontProjects/agent/smart-blog-agent/src/components/admin/content-editor-dialog.tsx)**：
  - 组件加载时 `GET /api/global-dynamic` 取得 `lib` 状态；`onSave` 时把绑定信息（`source`/`globalKey`）随 `config` 一并交回（主题侧仅持久化标志，不含全局 items）。
  - 「动态数据」与「自定义列表」区块标题行右侧加「+ 新增动态参数入库」按钮，打开小表单（复用 `Dialog` 基础组件）字段：名称、键、类型、label、itemTemplate、fieldMapping（键值对编辑器）、items（列表编辑，仅 `dynamic-list`），保存调用 `POST`。
  - 每个动态字段卡片：若 `lib[key]` 存在且未绑定 → 显示绑定提示与「绑定到全局」；绑定后 → 徽章 + 「解除绑定」（置回 `source:"theme"`，保留本地 items）。不在库中 → 「→ 加入全局参数库」。
  - 共享项编辑：绑定态下 items 编辑直接调用 `POST /api/global-dynamic` 写库并把合并后的副本用于预览。

## 假设与决策

- 复用按**字段键精确相等**匹配，绑定为**显式动作**（不自动覆盖主题本地数据，避免误改）。
- 绑定选择持久化在**主题 contentConfig 的该字段**（`source`/`globalKey`），库数据单独存在站点层；渲染时实时取库 → 库中编辑立即作用于所有绑定主题。
- 预览与真实渲染都传入 `getGlobalDynamic()`，保持一致。
- 主渲染、预览、自定义页三处调用点均需补入参；其余调用点（如生成会话 commit）若无需渲染可不动。
- 不做复杂共享冲突/权限控制，库为单用户全局字典，后写覆盖前写（先到先用，MVP 够用）。

## 验证步骤

1. `npx prisma migrate dev`（或 db push）后 `npm run generate`，类型检查通过。
2. `npm test`：新增渲染用例（绑定字段用库 items 渲染、未绑定用本地 items）并确认现有 106 用例仍绿。
3. 手工冒烟（`npm run dev`）：
   - 主题 A 定义一个 `dynamic-list`（键如 `site-links`）→ 点「加入全局参数库」并绑定。
   - 主题 B 用同样键 `site-links` 的动态字段 → 出现「绑定到全局」，绑定后预览使用库 items。
   - 在库中改 items → 主题 A、B 预览同步更新。
   - 解除绑定 → 主题回退到本地 items。
